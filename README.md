# Finance PWA — USD + UZS, с Supabase и Telegram-ботом

React + TypeScript + Vite PWA для личных финансов, с общим бэкендом на Supabase и Telegram-ботом
как serverless-функцией на Vercel. Интерфейс на русском.

## Что реально готово

- Dashboard: сегодня / неделя / месяц, доходы, расходы, чистая прибыль, график, цель.
- Доходы и расходы: создание, редактирование, удаление, поиск, категории, статусы.
- Источники дохода с долями и статистикой.
- Финансовые цели с прогрессом.
- Analytics и календарь.
- USD/UZS переключатель; исходная сумма и курс сохраняются в каждой операции.
- CurrencyService (`src/lib/currency.ts`) через open.er-api.com с кэшем последнего курса.
- **Вход по email (magic link) + Supabase Postgres как общее хранилище** — данные одинаковы
  на телефоне, компьютере и в Telegram.
- **Telegram-бот как serverless-функция** (`api/telegram.ts`) — без отдельного постоянно
  запущенного процесса, деплоится вместе с сайтом на Vercel.
- Если Supabase не настроен — приложение продолжает работать полностью локально
  (localStorage), как и раньше. Ничего не сломано для тех, кто просто хочет посмотреть UI.
- PWA: manifest, service worker, standalone-режим, safe-area, иконки.
- CSV-экспорт операций.

## Что сознательно упрощено (см. "Что стоит доделать" ниже)

- В боте валюта операции не спрашивается отдельным диалогом — сумма записывается в валюте
  профиля пользователя (Настройки → Валюта). Это сильно упрощает и ускоряет ввод; полноценный
  диалог "Валюта? UZS/USD" из ТЗ можно добавить по образцу того, как уже устроен выбор источника.
- Категория расхода в боте определяется по ключевым словам (`api/telegram.ts` → `CATEGORY_KEYWORDS`) —
  расширяйте список под свои привычки.
- Excel/PDF-экспорт не реализован (CSV — да). Push-уведомления не реализованы.
- Auth — только email magic link (без пароля). Это самый простой надёжный вариант для одного
  пользователя (дяди); полноценную многопользовательскую регистрацию можно не делать.

## Архитектура

```
                  Supabase (Postgres + Auth)
                    ▲                 ▲
                    │                 │
        anon key + RLS         service_role key
                    │                 │
              ┌─────┴─────┐     ┌─────┴──────┐
              │  Web App  │     │ /api/telegram │  ← Vercel serverless
              │ (Vercel)  │     │ (Vercel)       │     function, webhook
              └───────────┘     └────────────────┘
                    ▲                    ▲
                 браузер              Telegram
           (телефон/компьютер)      (сообщение боту)
```

Оба сервиса — Supabase и Vercel — управляемые (managed): после деплоя они работают сами,
без твоего компьютера. Vercel не держит бот отдельным процессом: Telegram сам присылает
сообщения на URL функции (webhook), функция запускается на долю секунды и засыпает —
это и есть "serverless", о котором просили в ТЗ, и заодно самый дешёвый/надёжный вариант
для Telegram-бота.

## Деплой с нуля (~15–20 минут, один раз)

### 1. Supabase (база данных + вход по email)

1. Зайди на supabase.com → New Project.
2. SQL Editor → вставь содержимое файла `supabase.sql` целиком → Run.
3. Authentication → Providers → убедись, что Email включён. Authentication → URL
   Configuration → добавь адрес будущего сайта (получишь на шаге 2) в Redirect URLs
   (можно вернуться и дозаполнить после первого деплоя на Vercel).
4. Settings → API — скопируй `Project URL`, `anon public key` и `service_role key`
   (последний — секретный, никогда не свети его в браузере/git).

### 2. Веб-приложение на Vercel

1. Залей папку `finance-pwa` в свой GitHub-репозиторий (или используй `vercel` CLI прямо
   из папки — `npm i -g vercel && vercel`).
2. На vercel.com → New Project → импортируй репозиторий. Framework Preset определится
   как Vite автоматически.
3. Project Settings → Environment Variables — добавь (Production + Preview):
   - `VITE_SUPABASE_URL` = Project URL из Supabase
   - `VITE_SUPABASE_ANON_KEY` = anon public key
   - `SUPABASE_SERVICE_ROLE_KEY` = service_role key (используется только в `api/telegram.ts`,
     в браузер не попадает)
   - `TELEGRAM_BOT_TOKEN` — получишь на шаге 3
   - `TELEGRAM_WEBHOOK_SECRET` — придумай случайную строку, например `openssl rand -hex 16`
   - `APP_URL` = будущий адрес твоего сайта, например `https://finance-uz.vercel.app`
4. Deploy. После первого деплоя скопируй реальный домен и, если отличается от того, что
   вписал в `APP_URL`, обнови переменную и передеплой (Redeploy).
5. Вернись в Supabase → Authentication → URL Configuration → впиши этот домен в Redirect URLs
   (иначе ссылка для входа по email будет вести не туда).

### 3. Telegram-бот

1. В Telegram напиши **@BotFather** → `/newbot` → задай имя и username → получишь токен вида
   `123456:ABC-DEF...`. Это и есть `TELEGRAM_BOT_TOKEN`.
2. Пропиши его в Vercel env vars (если ещё не сделал на шаге 2) и передеплой проект.
3. Установи webhook (замени значения на свои, выполни один раз с любого компьютера/телефона
   с интернетом — сам сервер это делать не обязан):

```bash
curl -X POST "https://api.telegram.org/bot<TELEGRAM_BOT_TOKEN>/setWebhook" \
  -H "Content-Type: application/json" \
  -d '{"url":"https://<твой-домен>.vercel.app/api/telegram","secret_token":"<TELEGRAM_WEBHOOK_SECRET>"}'
```

Ответ должен быть `{"ok":true,"result":true,...}`. С этого момента бот работает 24/7 —
никакой `node bot.js` запускать не нужно, Vercel сам вызывает `api/telegram.ts` при каждом
сообщении.

### 4. Первый вход и привязка дяди

1. Открой сайт (`APP_URL`) на телефоне или компьютере дяди → войди по его email → перейди
   по ссылке из письма.
2. В Telegram напиши боту `/start` → бот пришлёт 6-значный код.
3. В приложении: Настройки → Telegram → введи код → «Привязать».
4. Готово — теперь операции, добавленные в приложении и в боте, — это одни и те же данные.

## Финальная проверка ("выключи компьютер")

1. Сделай шаги выше на *своём* компьютере.
2. Выключи компьютер (или просто закрой ноутбук/отключи от интернета).
3. С телефона на мобильном интернете: напиши боту в Telegram `+500000 работа` — должен
   прийти `✅ Доход добавлен`.
4. С телефона открой сайт в Safari — операция должна быть видна на Dashboard.
5. Оба шага не зависят от того, включён ли твой компьютер: Supabase и Vercel работают
   сами по себе.

## Локальная разработка (по желанию, не обязательна для продакшена)

```bash
npm install
cp .env.example .env   # впиши VITE_-переменные; серверные (service role, bot token) для
                        # локального теста бота не обязательны — веб-часть работает и без них
npm run dev
```

Если `.env` не заполнен вовсе — приложение работает в локальном режиме (localStorage),
без входа по email, как и раньше.

## Установка на iPhone

1. Открой опубликованный HTTPS-адрес в Safari.
2. Share → «На экран Домой».
3. Запусти иконку — работает в standalone-режиме, как отдельное приложение.

## Что стоит сделать дальше (по приоритету)

1. **Диалог валюты в боте** — если операции в разных валютах через бот важны, добавь
   шаг "UZS/USD?" по образцу того, как уже выбирается источник дохода (`finalizeIncome`
   в `api/telegram.ts`), сохраняя draft в `bot_pending`.
2. **Реальный XLSX/PDF-экспорт** — подключить `xlsx` (уже есть в зависимостях для
   аналогичного экспорта в других частях кода) и, например, `pdfmake`.
3. **Web Push / напоминания** — для целей и повторяющихся доходов.
4. **Telegram Mini App** — сейчас кнопка «Открыть приложение» открывает обычную ссылку
   через `web_app`; для полноценного Mini App с автологином нужно верифицировать
   `initData` на сервере и завести отдельный auth-flow без email.
5. **E2E-тесты** (Playwright) на CRUD, конвертацию валют и мобильный вьюпорт.
